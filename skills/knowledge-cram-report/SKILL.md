# 知识点恶补 PDF 报告机制

> **[自研技能]** 名称：`knowledge-cram-report` ｜ 用途：任务收尾时从既有留痕（`plan.yaml` / `trace.jsonl` / 交付物）现场抽取知识点 → 去重 → 按五段式通俗化 → 渲染成带公式与自测题的 PDF，并按**项目名分层归档**、附 FSRS 形状的复习调度与索引台账 ｜ 适用场景：任意 L2 任务收尾、或用户说「给这个任务出一份恶补报告 / 知识点 PDF」时；**不适用于**把会话原样转录（本机制铁律是「不转录，只抽取」） ｜ 仓库：https://github.com/Garvin666/ai-workflow-tools/blob/main/skills/knowledge-cram-report/SKILL.md

## 一句话定位

> **每次任务收尾，把这次真正学到的东西抽出来、用自己的话讲一遍、渲染成一份带公式和自测题的 PDF，
> 按项目名归档进 `恶补` 文件夹，并在索引里排好下次复习的日期。**

它**不是会话记录器**。GitHub 上那个 15,388 星的 `claude-obsidian` 在自家 README 里写着
*"This is **not an automatic transcript recorder**"*，甚至把 `save` 技能的职责规定成
*"Saves one scoped answer or insight—**never an automatic transcript**"*。
一个专做知识管理的项目把「不要自动转录」写在最显眼处 —— 说明无差别转录会产出垃圾。
**本机制的价值全在「抽、去重、讲人话」这三步上。**

## 铁律

1. **不转录，只抽取。** 入选判据两条，必须同时满足：**可迁移**（换个任务还用得上）+ **可解释**（能用一句自己的话讲清）。
   讲不清的**不写进正文**，而是归入「本次未消化」清单 —— 那份清单反而最该看。
2. **数值只有一个源。** 复习间隔一律由 `cram_index.interval_days()` 产出。
   报告正文、索引、配图、任何说明文档里出现的间隔数字，都必须来自它。
   > 为什么写成铁律：上一轮就是因为「四处各写各的」，同一份报告里正文写「第三次间隔 10 天」、
   > 答案里用同一公式算出 4 天 —— **整页自相矛盾却 8 条判据全过**（那 8 条里没有一条查数值自洽）。
   > 现在这条由 **V9 判据实跑核对**。
3. **归档必须按项目名分层。** 项目名**必须显式给出**，不猜默认 ——
   猜错会把报告静默归到错误分区，而「文件名合规」这类判据查不出「放没放对」。
   现在这条由 **V10 判据实跑核对**。
4. **判据自己先跑一遍。** 新增或修改任何判据，先跑 `--selftest`（含阴性 + 阳性对照）。
   不跑，清单里会带着 bug 上线，用户看到的就是一份「永远有几条红」的报告，久而久之没人再看。
5. **SKIP 不是 PASS。** 未检测 ≠ 通过。缺 before 基线、缺项目名、缺知识点条数声明 —— 一律记 SKIP 并写明原因，
   不得并入通过率。
6. **内发与外发要分开。** 归档目的地是本机桌面 ⇒ 属**内发**，此时绝对路径不是泄露
   （报告正文可能正在讲那条路径本身）。V4b 只在**外发**时参与判定。
7. **改既有报告前先备份。** 数值或版式返修会重写归档里的文件；改前留副本 + sha256，改后回读断言。

## 归档结构（按项目名分层）

```
<归档根>\                              # 例如 C:\Users\26717\Desktop\恶补
├── 00-索引.md                         # 唯一去重事实源 + 复习调度台账（脚本维护，勿手改）
├── _assets\
│   ├── 恶补模板.md                     # 报告骨架模板
│   └── 恶补模板.tex                    # 版式导言区（pandoc --include-in-header）
├── <项目名>\
│   └── <年-月>\
│       ├── YYYY-MM-DD_<任务短名>_恶补报告.md     # 可编辑源
│       ├── YYYY-MM-DD_<任务短名>_恶补报告.pdf    # 阅读载体
│       └── <日期>_<任务短名>-fig1-*.png          # 配图（与报告同目录，**相对路径**引用）
└── <另一个项目名>\...
```

- **项目名**：默认取该任务的工作区目录名；跨项目的工作区用 `--project` 显式指定。
- **为什么同时留 `.md`**：PDF 是阅读载体，`.md` 是可编辑源。想改版式、想合并成册、想再加工，不必重新生成。
- **为什么配图用相对路径**：搬家不断链；也不再让 V4b 报一堆绝对路径。
- **为什么按年-月分层**：归档工具按 `YYYY-MM` 分组，手工平铺会让「数出来 N 项」被误读成失败。
  两种结构并存过一次，这里是刻意只保留一种。

## 七步流程

```
任务收尾
  ├─① 取料：plan.yaml / trace.jsonl / Ledger.md / 交付物 / 对话要点      （全部是既有留痕，不新造数据）
  ├─② 抽取：可迁移 + 可解释 两条判据，每条挂来源锚 + 掌握分级 + 一句话摘要
  ├─③ 去重：与 00-索引.md 比对 —— 全新 / 有增量 / 纯复习
  ├─④ 通俗化：五段式（定义 → 为什么 → 最小算例 → 常见误解 → 与已学连接）
  ├─⑤ 渲染：cram_render.py（全本地 pandoc + xelatex）
  ├─⑥ 归档：cram_index.py place 派生落点 → 写报告 → upsert 索引 → 算下次复习日
  └─⑦ 校验：V1–V11 全过（FAIL=0）才算成；SKIP 逐条写明原因
```

**触发**：① ai-workflow 阶段 6 收尾（主触发，L2 默认）；② 用户手动一句「给这个任务出一份恶补报告」。
**不触发**：L0 轻操作（改一行字、查个命令、问个概念）—— 生成报告反而是噪声。
**L1 任务默认跳过**，可在 `plan.yaml` 里显式打开。

## 抽取判据（写正文前先过这一关）

**来源 → 抽什么**

| 来源 | 抽出什么 |
| --- | --- |
| `plan.yaml` | 每步「做什么 / 验证方式」→ 方法类知识点；`决策记录` → 取舍类；`计划修订` → 为什么改主意 |
| `trace.jsonl` | 失败与重试记录 → 踩坑类（**最有价值的一类**） |
| `Ledger.md` | 任务定位与结论 |
| 交付物正文 | 领域知识本身 |
| 对话里的用户纠正 | 偏好类（「别这样」「以后都照这个来」） |

**硬排除（不写入报告）**：一次性环境噪声（临时路径、端口、会话 ID、时间戳）、纯操作步骤、
**凭据 / 令牌 / 个人隐私**（硬禁止，无例外）、只有结论没有推理的断言。

**每条知识点必带三样**：`来源锚`（哪个任务、哪个步骤）+ `掌握分级`（A 已掌握 / B 见过没细想 / C 全新）+ `一句话摘要`。

## 五段式写作规范（缺段即不合格）

1. **一句话定义** —— 不用术语解释术语。
2. **为什么需要它** —— 不解决什么问题？没有它会怎样？
3. **一个最小算例** —— 必须**带具体数字**。公式尤其要给一组数算一遍。
4. **常见误解** —— 最容易错在哪。
5. **与已学连接** —— 锚到**已经会**的最近邻概念（「这其实就是你学过的 ⋯ 的连续版本」）。

**长度**：单条 150–400 字。宁可短而准，不要长而空。

**禁止**（这几条正是「AI 味」最容易堆出来的地方）：
四字格排比凑字数 · 「不是 A，而是 B」反复出现 · 只贴结论不给推理 · 用更多术语解释一个术语 ·
无信息量的过渡句（「值得一提的是」「综上所述」）。

详见 `references/写作规范.md`（含报告骨架 7 块与去味清单）。

## 判据 V1–V11

| # | 判据 | 口径要点 |
| --- | --- | --- |
| V1 | 命名合规 | `^\d{4}-\d{2}-\d{2}_.+_恶补报告\.pdf$` |
| V2 | 可解析且含中文 | 页数 ≥1、提取字符 ≥200、**不同汉字 ≥5** |
| V3 | 公式源码零泄漏 | 检查 `\frac` / `$$` / `\section` / `\begin{` 等 —— **但源码代码块里故意引用的是教学内容**，按配额放行；超配额才 FAIL |
| V4a | 凭据与隐私零命中 | `sk-` / `ghp_` / `PRIVATE KEY` / 身份证 / 手机号 / 邮箱，**任何场景都查** |
| V4b | 本机绝对路径 | **仅外发场景**判 FAIL；内发判 SKIP 并逐条给性质判定 |
| V5 | 索引已追加 | 必须给 **before 行数基线**；只验「含本日期」是恒真的弱判据 |
| V6 | 来源锚数 == 知识点条数 | 知识点条数缺省由 md 的 `### N.` 标题数推得 |
| V7 | 自测题与答案齐备 | 题号正则 `第\s*\d+\s*题`；**题数 ≥3 且答案数 == 题数**（题号不得硬编码） |
| V8 | 生成耗时 | **冷 ≤600 s / 热 ≤20 s 两档**；单次超热阈值时自动补测一次，两个数都留 |
| **V9** | **复习间隔数值自洽** | 文中每处「S=… ⇒ N 天」都必须等于 `interval_days(S)` |
| **V10** | **归档路径按项目分层** | 反推应然目录 `根/项目/年-月`，实际目录必须一致 |
| **V11** | **结构完整性 + 台账自洽** | ① `cram_render` 查 md 有无**残缺/孤立的表格行**（替换没替换干净的「半张表」）；② `cram_index verify` 查每行 `S == 1.9^(出现次数-1)` 且 `下次复习 == 日期 + interval_days(S)` —— 专抓「把 S 当逐行推进的游标」的**行间串扰** |

> **V3 / V4b 的共同道理**：判据报红时先问「**这个输入是这条判据该吃的吗**」。
> 「讲解型产物引用了 LaTeX 示例」「报告在讲某条路径本身」都不是泄露 ——
> 把它们判 FAIL，就是把「教材引用了例子」误判成「泄露了秘密」。

## 脚本用法

```bash
S=~/.workbuddy/skills/knowledge-cram-report/scripts          # 下文以 $S 代指

# 0) 环境自检（缺依赖就明确报错，退出码 3，**不静默降级**）
python $S/cram_env.py

# 1) 派生归档落点（唯一口径源）
python $S/cram_index.py place --root "C:/Users/26717/Desktop/恶补" \
    --project 工作流 --date 2026-10-07 --task 实施-知识点恶补报告机制

# 2) 写报告（md 需先按模板写好在落点目录里）
#    --index-before 给本轮写前的行数；首写默认 --expect-added 1，
#    重渲染一份**已进台账**的报告（无新增行）时传 --expect-added 0，否则 V5 会误红。
python $S/cram_render.py --src "<落点>/YYYY-MM-DD_<任务>_恶补报告.md" \
    --out "<落点>/YYYY-MM-DD_<任务>_恶补报告.pdf" \
    --index "C:/Users/26717/Desktop/恶补/00-索引.md" --index-before <本轮写前的行数> \
    --expect-added 1 \
    --dest-root "C:/Users/26717/Desktop/恶补" --project 工作流 \
    --template "C:/Users/26717/Desktop/恶补/_assets/恶补模板.tex" \
    --evidence "<任务目录>/证据"

# 3) 写索引（三态判定；同一 report_id 重跑幂等，不重复计数）
python $S/cram_index.py upsert --index "C:/Users/26717/Desktop/恶补/00-索引.md" \
    --project 工作流 --date 2026-10-07 --task 实施-知识点恶补报告机制 \
    --items "<任务目录>/tmp/items.json"

# 4) 今天该复习什么
python $S/cram_index.py due --index "C:/Users/26717/Desktop/恶补/00-索引.md"

# 5) 台账自洽校验（V11 血缘）：S 须由出现次数递推、下次复习须由 S 派生
#    报红即「行间串扰」——某几行继承了不该属于它的递进 S（迁移/手写台账最容易犯）
python $S/cram_index.py verify --index "C:/Users/26717/Desktop/恶补/00-索引.md"

# 6) 判据自测（阴性 + 阳性对照；改判据后必跑）
python $S/cram_render.py --selftest
python $S/cram_index.py selftest
```

`items.json` 形态：

```json
[{"标题": "判据的输入口径要单独问一次", "关键词": "口径错配/判据该吃什么", "分级": "B",
  "有增量": false, "来源锚": "2026-10-07 某任务 步骤 2"}]
```

- `有增量: true` ⇒ 判为「有增量」，正文需追加「补充（YYYY-MM-DD）」小节，索引 `出现次数 +1`、`S × 1.9`。
- `有增量: false`（缺省）⇒ 命中既有标题时判为「纯复习」，**不重写正文**，索引仍 +1、`S × 1.9`（都算一次复习）。

## 诚实边界（不假装有保证）

| 事项 | 实情 |
| --- | --- |
| **知识点选得对不对** | **没有机器判据**。抽取质量只靠读后反馈。这是本机制最弱的一环，如实登记 |
| 去重 | **字面级**；同义改写（「别忘加测试」vs「测试要补上」）会各自成条，稀释计数。语义级属后续版本 |
| 触发 | 靠流程纪律，**不是宿主强制**（`skillOverrides` 管的是技能可见性，管不了触发时机）。漏了说一声即可 |
| V3 的配额放行 | 配额按**源码代码块**统计，无法区分「同一 token 既在代码块里、又泄漏在正文」。属**已知的粗粒度**，不是精确判定 |
| V9 的形态识别 | 只认「`S=…` 与「间隔 … 天」出现在同一小句」的写法。写法太自由会落到 SKIP（未检测，不是通过） |
| 台账被手改 / 迁移过 | **必须跑一次 `cram_index verify`**。台账里若某行继承了不属于它的递进 S（如把 S 当成逐行推进的游标），各判据都不会红，只会让复习调度整体偏晚 —— 这类错只有 `verify` 抓得到 |
| 报告目录 | 由 `_render` 与 `REPORT_COLS` **同列数**生成；列数一旦不一致，`parse_index` 读不回来 ⇒ 「报告总数」恒为 1、每次 upsert 丢掉上一份报告行（曾实测）。改 `REPORT_COLS` 时须同步改 `_render`，`selftest` 的 ST14 往返夹具会挡住 |
| 环境依赖 | pandoc + MiKTeX **不在版本控制里**，换机器会断；故每次生成前先跑 `cram_env.py`，缺了就明确报错 |
| 「通俗」 | 无机器判据。可用 ai-workflow 的 `humanize_scan.py` 做机器档筛查，但语义档只能人审，且它不是 AI 检测器 |
| 公式可选中复制 | 不同 PDF 阅读器对 LaTeX 生成的字形支持不一，**不保证**整段公式可选中复制 |
| 写入 `Desktop\恶补` | 该路径在工作区根之外 ⇒ 是一次**越界写入**，须在任务 `plan.yaml` 登记 `越界授权` |
