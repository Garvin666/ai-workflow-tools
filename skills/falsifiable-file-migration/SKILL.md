# 可证伪的文件搬运

## 什么时候用

要把一个目录或一批文件**从 A 挪到 B**，且满足任一条：

- 源目录**只有一份**（没有任何备份能兜底）
- 源位置**本身要被清空**（桌面、临时区、旧盘）
- 这次搬运**跨盘**（`C:` → `E:`）
- 搬完之后你要**向别人声明「没丢东西」**

典型的触发句：「移入工作区」「把这个目录搬到 D 盘」「整理一下归档根」「换个 home」。

**不需要**：同盘改个名、`git mv` 跟踪文件（版本控制本身给了退路）、纯新增复制（源不动，没有丢的风险）。

## 四条铁律

1. **不用 `move`/`mv`/`rm`，用「复制 → 对账 → 送回收站」三步。**
   `move` 跨盘的本质是「复制 + 删除」：中途失败会留下**半搬状态**，而且事后很难判断哪一半是新的哪一半是旧的。拆成三步后，中间态**可证伪**（见下节），失败停在中间也不丢数据。

2. **对账口径是「逐文件 sha256 逐一相等」＋「文件数相等」，两者都要。**
   只看文件数会漏掉「换了一个同名但内容不同的文件」；只看 sha 集合（排序后比）会漏掉「两个文件互换名字」。所以口径是**按相对路径配对的逐文件比对**，而不是两个集合的比较。

3. **原件送回收站，绝不硬删。**
   这一步的全部价值就在于**留住退路**。硬删把「可回滚」变成「不可回滚」，把一次普通操作升级成不可逆动作。跨平台做法：
   - Windows：`SHFileOperationW`（`winshell` / `send2trash` 亦可）带 `FOF_ALLOWUNDO`
   - Linux：`gio trash` 或 `trash-put`
   - macOS：`osascript` 调 Finder，或 `trash` CLI
   若目标平台**没有**回收站机制，**先停下告知**，取得确认再谈删除 —— 不要默默降级成 `rm`。

4. **「已送回收站」本身也是要被核验的声明。**
   跑完回收 API 不等于东西真的进了回收站。要**独立**去回收站里找到对应的条目，比对**原路径**与**字节数**。这一步和「验证服务端吊销是否生效」是同一类纪律：**别只信口头与自报**。

## 三步法

### 第 1 步 · 复制

```python
import shutil, os
shutil.copytree(SRC, DST, dirs_exist_ok=True)   # 复制，源保持不动
```

先**清点源**并落盘基线（文件数 + 每文件 sha256），这份基线就是第 2 步的对账依据、也是事后审计的物证。

### 第 2 步 · 对账（这一步就是「可证伪的中间态」）

```python
import hashlib, os
def digest(p):
    h = hashlib.sha256()
    with open(p, "rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return h.hexdigest()

def tree(root):
    out = {}
    for dp, _, fn in os.walk(root):
        for f in fn:
            full = os.path.join(dp, f)
            out[os.path.relpath(full, root).replace("\\", "/")] = (digest(full), os.path.getsize(full))
    return out

before, after = tree(SRC), tree(DST)
assert set(before) == set(after), "相对路径集合不等"
diff = [k for k in before if before[k][0] != after[k][0]]
assert not diff, f"内容不一致：{diff}"
```

**必须逐文件配对比**，理由见铁律 2。多一层便宜保险：`os.path.getsize` 一并比，能在 sha 之前就快速暴露截断。

### 第 3 步 · 送回收站 + 独立核实

送回收站后，**另起一段逻辑**去核实（不要复用「发送」那条路径的返回值）：

- 确认**源位置已不存在**。
- 去回收站里**找到**对应条目，比对原路径与字节数。
- Windows 回收站结构：`C:\$Recycle.Bin\<SID>\` 下每个被删项是一对文件 ——
  `$I<name>` 是索引记录，`$R<name>` 是数据本体。`$I`（version ≥ 2）的**实测**布局：

  | 偏移 | 长度 | 含义 |
  | --- | --- | --- |
  | `[0:4)` | 4 | 版本（= 2） |
  | `[8:16)` | 8 | 文件字节数（u64 小端） |
  | `[16:24)` | 8 | 删除时间（FILETIME） |
  | `[24:28)` | 4 | **路径长度**（u32 小端；UTF-16 码元数，**含结尾 NUL**） |
  | `[28:)` | — | **原路径**（UTF-16LE，NUL 结尾） |

  ⚠️ **路径起于 28，不是 24。** 把 24 当起点会解出一个乱码首字符（实测 `'r'` / `'+'`），
  而记录看上去**仍然「解出来了」** ⇒ **静默错配**，比直接抛错更难查。校准证据：一条真实记录的
  `[24:28) = 43`，恰等于它 42 字符的原路径 + 1（NUL）。
- **同盘里还有 SYSTEM / 别的账户的 SID 目录，当前用户读不了** —— 这是**常态**，跳过即可，不是错误。
- 记录可能有**十几万条**（临时文件常年堆积）⇒ 按 `$I` 的 **mtime 降序**扫描、命中即提前退出；
  别为两个文件把十万条读完。

独立核实 = 解析出 (原路径, 字节数)，与「应被回收的那批」**按路径配对**比对（计数 + 逐项字节数）。

## 迁移前必须做的两件事

### ① 旧路径的「引用点全集」排查

迁移会**打断硬编码路径依赖**。移之前，先在相关仓库里 grep 旧路径，把命中分成两类：

| 类别 | 判据 | 处置 |
| --- | --- | --- |
| **活引用** | 会被程序读、会被拿去解析成真实文件（脚本里的常量、技能手册里的路径口径、计划文件里的交付物字段） | **必须改** |
| **历史留痕** | 记录「当时发生了什么」（日志、台账、证据、审计报告、不可逆动作登记） | **不该动** —— 改了就是改历史 |

漏一个活引用，就留下一条**悬空路径**；更隐蔽的是它不一定会立刻报错（比如手册里的示例），直到下一次有人照着执行才炸。

### ② 检查「改判据的调用方」

⚠️ 如果旧路径同时出现在某个**计划文件**里、且被登记为**某一步的交付物**，那么迁移完成那一刻，那个计划对账就会**悬空 FAIL** —— 因为交付物不存在了。

判据的输入变了，判据本身就得跟着走。这不是「把判据改宽松以便消 FAIL」（那是严禁的），而是**同步更正输入**：把交付物字段改成新位置。收尾时要**同时**复跑迁移前受影响的计划对账，确认归零。

> 推广一句：**改任何判据/口径前，影响面要扫两个域** —— ① 受检对象本身；② 把该判据的**输出**当前置输入的下游脚本。只扫 ① 是常见疏漏。

## 反模式（踩过的）

- ❌ `shutil.move` / `mv` 直接搬 —— 半搬状态不可证伪，失败后说不清哪半是新的。
- ❌ `rm -rf` / `shutil.rmtree` 原目录 —— 把可回滚做成不可回滚；用户改主意时只能靠回忆重建。
- ❌ 只比文件数就说「没丢」 —— 挡不住「同名不同内容」。
- ❌ 跑完回收 API 就宣布「已删除」 —— 不去回收站核实，等于只信自报。
- ❌ 迁移前不 grep 引用点 —— 留下一堆悬空路径，且不会立刻报错。
- ❌ 迁移后只跑新任务对账、忘了复跑**被牵连的旧任务**对账。
- ❌ 归档/搬运临时文件时用**通配符**（`Move-Item tmp\*.py`）—— 共享的中间目录里可能躺着别人正在用的文件，会一并搬走。
- ⭐ ❌ **自测夹具按被测逻辑反推** —— 手写一条「自己以为对」的回收站记录去测解析器，
  只能证明**自己和自己自洽**。这类夹具会**全绿**，而真实记录一条也匹配不上：
  实测中解析偏移写错 4 字节（24 而非 28），合成夹具照样通过，只有**穿真实系统**的
  往返测试才暴露它。正解两条**都要**：① 夹具布局对**真实样本**校准（把 hexdump 证据写进注释）；
  ② 保留一个真删 → 真读 → 真还原的端到端对照（本脚本的 `--selftest --live`）。
  **能自洽 ≠ 对得上现实**；阴性对照必须**非退化**、且方向对得上生产真相。
- ❌ 把「送回收站的动作成功」当成「已进回收站」—— 有的卷被策略配置为**删除时不使用回收站**，
  此时带着 `FOF_ALLOWUNDO` 的调用也会**静默硬删**、不报错（fail-open）。
  这就是为什么第 4 条铁律要求**独立核实**：硬删之后回收站里查不到记录，核实必 FAIL。

## 参考实现

`scripts/migrate_falsifiable.py` —— 把三步法封成子命令：
`plan`（清点源 + 落基线 + 打印清单，只读）→ `run`（复制 + 逐文件对账，**不删源**）→
`trash`（把源下每个文件送回收站）→ `verify`（独立核实，读**真实**回收站记录，按路径 + 字节数配对）。

自测分两级，**两级都要**：
- `--selftest`：**逻辑对照** —— 改 1 字节 / 少一个文件 / 字节数不符 / 路径不在回收站 ⇒ 判据必须变红；完全一致 ⇒ 必须判绿。
- `--selftest --live`：**穿真实系统的对照** —— 真送回收站 → 读真实记录核实 → 真还原 → 与基线逐文件相等。

**没有阴性对照的守卫只是个恒绿的摆设**；而只有逻辑对照的守卫，还可能是「自洽但不对现实」（见反模式第一条）。
